# 密码库

把网站账号、API key、服务器和设备的登录信息存在 xpanel 里。内容用一个主密码加密，主机上、备份里、外置硬盘上只有密文。

入口：左侧导航的「密码库」。桌面版和浏览器里的网页版都能用。

---

## 1. 怎么用

### 第一次：设主密码

1. 点「密码库」，输两遍主密码，勾上「我知道忘了就打不开」，点「创建密码库」。
2. 主密码至少 10 个字符。它不保存在任何地方，**忘了没有找回的办法**，里面的内容就打不开了。
3. 建议用一句自己记得住的长话，别和其他地方的密码一样。

### 存一条

点「新建」，选种类，填名称和内容，保存。

| 种类 | 里面有什么 |
|---|---|
| 网站账号 | 网址、用户名、密码 |
| API key | 服务或网址、账号、Key / Token |
| 服务器和设备 | 地址、用户名、密码 |

- 每种都有「备注」，还可以「加一栏」放端口、数据库名、私钥、恢复码等，每一栏可以选平时显示还是隐藏。
- 密码框右边的骰子按钮生成一个 20 位的随机密码。
- **名称不加密**：锁着的时候、给 AI 的列表里、合并时都看得到。别把密码写在名称里。

### 看和复制

- 选中一条，鼠标移到某一栏上，右边出现「复制」；密码和隐藏的栏还有「显示」。
- 搜索框搜名称、网址、用户名、备注（解锁后才搜得到加密的部分）。

### 锁上和解锁

- 十分钟不碰密码库会自动锁上；点列表上方的锁图标可以马上锁上；刷新页面、重开程序也会锁上。
- 解锁要算大约一秒（故意的，让别人猜密码变慢）。

### 改主密码

列表上方的钥匙图标。改完马上生效，条目不用重新加密。
别的电脑合并到这次修改之后，也要用新的主密码；以前的备份还是用当时的主密码。

## 2. AI 取用

AI（Claude Code、Codex 等，通过 MCP）不能直接读密码库：

1. 它只能先看到有哪些条目：名称和种类，没有内容（`xpanel_vault_list`）。
2. 它要用某一条时发一个请求，说明用途（`xpanel_vault_get`）。
3. 开着的 xpanel 界面（桌面版或网页版）会弹窗：谁、要用哪一条、它说的理由。
4. 你点「允许这一次」，那一条的全部内容才会交给它；点「拒绝」或两分钟不理，它什么都拿不到。

- 每次取用都要确认，没有「以后都允许」。
- 密码库锁着时，弹窗里会让你先输主密码。
- 关掉弹窗不算拒绝，只是先不看，请求两分钟后自己作废。
- 允许和拒绝都会记在操作记录里（谁、哪一条、什么时候）。
- 弹窗里的理由是对方自己写的，不一定可信。不是你刚让它做的事，就点拒绝。
- 交出去的内容你就管不了了：AI 会在它自己的对话里看到明文。只把它用得着的那一条给它。

「交给 AI」展开的项目目录、评论里 @AI 带的上下文、条目的导出和搜索里都没有密码库的内容。

## 3. 多台电脑

- **连接到主机的电脑、浏览器**：密码库在主机上，随时是最新的。连不上主机时用不了密码库（离线缓存里没有它）。
- **外置硬盘同步**：密码库跟着一起合并，不用选。
  - 只有一台电脑改过的条目，跟着改；一台电脑删了的，跟着删。
  - 两台电脑都改了同一条：留较新的，较旧的另存成一条，名称后面带「（合并时保留的旧版本）」。看过之后自己删掉不要的。
  - 主密码以较晚改的那次为准。
- **两台电脑各自设了主密码，后来才合并**：两边的条目都在，各用各的主密码。
  - 解锁时输哪个主密码，就解开哪一边的条目；另一边的显示「用另一个主密码加密的」，点开输另一个主密码就能看。
  - 想以后输一次就全解开：用「改主密码」把其中一个改成和另一个一样。
  - 最好一开始只在一台电脑上设主密码，其他电脑通过合并或连接主机拿到它。

## 4. 安全方面你需要知道的

**加密是怎么做的**

- 加密、解密都在界面里做（你面前这台电脑的 xpanel 窗口或浏览器页面）。主密码和解开的内容不发给主机，也不写到硬盘。
- 主密码经过 scrypt（N=2^17, r=8, p=1）算出一个密钥，用它把随机生成的「密码库密钥」包起来存在主机上。
- 每一条的内容用密码库密钥加密（XChaCha20-Poly1305，每次保存换一个随机数）。
- 交给 AI 的那一条，用它请求里带的临时公钥加密（X25519 + HKDF-SHA256 + XChaCha20-Poly1305）后经主机转交，主机和局域网上看不到明文。
- 用的是经过审计的开源库 `@noble/ciphers`、`@noble/hashes`、`@noble/curves`（界面）和 RustCrypto 的 `chacha20poly1305`、`x25519-dalek`、`hkdf`（命令行）。

**它防得住什么**

- 别人拿到数据库文件、备份、外置硬盘：只有密文和名称，没有主密码打不开。
- 局域网里有人抓包：网页版走的是明文 HTTP，但密码库的内容在发出去之前已经加密了。
- AI 通过接口或 MCP 乱翻：拿不到内容，除非你点了允许。

**它防不住什么**

- **主密码太弱**：密文和包着的密钥在局域网里谁都能从接口读到（xpanel 的接口在局域网内不需要登录），弱密码可以被离线猜出来。主密码是唯一的防线。
- **你用的这台电脑不干净**：键盘记录、恶意浏览器插件、别人能动你解锁着的电脑，都看得到解开的内容。
- **局域网里有人篡改网页**：网页版是明文 HTTP，能改数据包的人可以把页面换成偷主密码的版本。不放心的网络里只用桌面版，或者等远程访问（Tailscale）做好后走加密通道。
- **名称和数量**：名称、种类、有多少条、什么时候改的，都是明文。
- **改了主密码之后的旧备份**：旧备份里的密码库用旧主密码就能打开。主密码泄露了的话，除了改主密码，还要把里面的密码逐个换掉。
- **复制到剪贴板的内容**：不会自动清掉。

## 5. 出问题时

| 情况 | 怎么办 |
|---|---|
| 忘了主密码 | 没有办法找回。只能到各个网站重置密码后重新存 |
| 「这一条在别处刚改过，请刷新后再改」 | 另一台电脑或另一个窗口刚改了同一条。重新选中它再改 |
| 「主密码在别处刚改过」 | 别处刚改了主密码。刷新页面，用新的主密码解锁 |
| 「打不开密码库……连不上主机」 | 密码库存在主机上，等连上主机再用 |
| 合并后多了「（合并时保留的旧版本）」 | 两台电脑都改了同一条。对比一下，删掉不要的那条 |
| 误删了一条 | 从每天的备份里找回：见 [drive-sync.md](drive-sync.md) 第 5 节恢复数据库的办法（整库恢复） |

## 6. 实现说明（给开发者）

- 数据库（schema v6）：`vault_keys`（钥匙：`kid`、`data` = `{kdf, salt, n, c}`）、`secrets`（`id`、`kid`、`title`、`kind`、`data` = `{n, c}`，软删除）。和 `items` 分开，所以不会进条目的列表、搜索、导出、旧界面的 `/api/state`。
- 存储：`crates/xp-store/src/vault.rs`。修改带 `expect`（上次看到的 `updatedAt`），对不上返回冲突。取用请求只在内存里（`Store.vault_requests`），两分钟过期，批准后取走一次就删。外置硬盘合并在同一个文件的 `merge_vault`（`sync.rs` 的 `merge_apply` 调它）。
- 接口：`crates/xp-server/src/vault.rs`，`/api/v1/vault`、`/vault/index`、`/vault/keys/{id}`、`/vault/secrets/{id}`、`/vault/requests`、`/vault/requests/{id}`。
- 界面：`web/src/lib/vault.ts`（加解密、解锁状态、读写）、`web/src/components/Vault.tsx`（整页 + `VaultRequests` 弹窗，挂在 `App.tsx`）。
  用纯 JS 的 @noble 库而不是 `crypto.subtle`：局域网里用 `http://主机:8765` 打开时浏览器不提供后者。
- MCP：`crates/xp-cli/src/vault.rs`（临时密钥、等确认、解开）+ `mcp.rs` 的 `xpanel_vault_list`、`xpanel_vault_get`。
- 格式里的常量：钥匙的附加数据 `xpanel-vault-key-v1`，条目的 `xpanel-vault-secret-v1`，取用请求的 HKDF info `xpanel-vault-request-v1`（盐是「界面的临时公钥 ‖ 请求方公钥」）。改格式时换一个版本号，别原地改。
- 测试：`cargo test -p xp-store vault`、`cargo test -p xp-server vault`、`cargo test -p xp-cli`。界面的端到端测试还没进仓库（做法见 development.md 第 5 节：在明文 HTTP 的非 localhost 地址上走一遍，确认数据库文件和请求里都没有明文）。
