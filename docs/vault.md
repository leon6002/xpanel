# 密码库

把网站账号、API key、服务器和设备的登录信息存在 xpanel 里。内容用一个主密码加密，主机上、备份里、外置硬盘上只有密文。

入口：左侧导航的「密码库」。桌面版和浏览器里的网页版都能用。

---

## 1. 怎么用

### 第一次：设主密码

1. 点「密码库」，输两遍主密码，勾上「我知道忘了就打不开」，点「创建密码库」。
2. 主密码至少 12 个字符，纯数字和带 password、1234、qwer 这类常见写法的不让用。它不保存在任何地方，**忘了没有找回的办法**，里面的内容就打不开了。
3. 建议用一句自己记得住的长话（20 个字符以上），别和其他地方的密码一样。

### 随手记一条，之后再整理

临时要记个账号密码、马上还要回网站接着干别的，用这个：

- **快速记录里选「密码」**（右下角的加号，类型那一排最后一个）。随便怎么写，比如 `阿里云 me@example.com Abc123!@#`，回车就存进密码库。
- **收件箱的输入框**里打的字如果像账号密码，输入框上面会出现「看起来是账号密码，点这里存进密码库」，点它就不进收件箱、直接进密码库。
- **已经发进收件箱的消息**：鼠标移上去，点工具栏里的「密码库」。它会转进密码库，原消息从主机上抹掉（以前做的备份里还有）。

这样存的条目：

- **密码库锁着也能存**，不用输主密码。存进去之后要解锁才看得到。
- 整段加密，不经过条目和收件箱，不会进搜索和导出。
- 先标成「待整理」，在主机上的名称只有「待整理 · 时间」。侧栏「密码库」旁边的数字是还有几条没整理。
- 升级前建的密码库，要先解锁一次才能这样存。

### 整理

密码库里「待整理」排在最上面。点开一条，点「整理」：程序会把原文拆成名称、网址、用户名、密码，预填到表单里，
你看一眼、改掉不对的再保存。拆分只在这台电脑上做，不会交给 AI。原文留在一个平时隐藏的栏「原文」里，不需要了可以删掉那一栏。

不整理也没关系，搜索时照样找得到。

### 新建一条

点「新建」，选种类，填名称和内容，保存。

| 种类 | 里面有什么 |
|---|---|
| 网站账号 | 网址、用户名、密码 |
| API key | 服务或网址、账号、Key / Token |
| 服务器和设备 | 地址、用户名、密码 |
| 其他 | 不属于上面几种的：恢复码、Wi-Fi 密码、门禁、证件号… |

- 每种都有「备注」，还可以「加一栏」放端口、数据库名、私钥、恢复码等，每一栏可以选平时显示还是隐藏。
- 密码框右边的骰子按钮生成一个 20 位的随机密码。
- **名称不加密**：锁着的时候、给 AI 的列表里、合并时都看得到。别把密码写在名称里。待整理的条目名称只有时间。
  （密文里另有一份名称，解锁后界面显示的是那一份；两份对不上时详情里会提醒。）

### 找

**在任何页面按 Ctrl+K**（Mac 上是 ⌘K）弹出搜索框，不用先进密码库：

- 打几个字，回车复制密码（API key 那种是复制 key），Tab 复制用户名，Ctrl+回车打开这一条。
- 密码库锁着时，先在搜索框里输主密码。
- 还没打字时显示置顶的和最近用过的。

搜索（搜索框和密码库页面里的一样）：

- 搜名称、网址和域名、用户名、标签、自己加的栏的名字、备注、待整理的原文。不搜密码本身。
- 只打一部分、漏几个字母（`gthb` 找到 github）、错一个字母、多个词不分顺序，都能找到。
- 常用的、最近用过的、置顶的排前面。「用过」只记在这台电脑的浏览器里。

密码库页面里：

- 列表分几段：待整理、置顶、最近用过、其他。同一个网站的几个账号排在一起。
- 列表上方可以按种类和标签筛选。
- **标签**在编辑时填，空格分开，一条可以有多个。**置顶**点详情右上角的图钉。标签和置顶都在密文里，锁着时和给 AI 的列表里看不到。

### 看和复制

- 选中一条，鼠标移到某一栏上，右边出现「复制」；密码和隐藏的栏还有「显示」。

### 锁上和解锁

- 十分钟不碰密码库会自动锁上（电脑睡过去再醒来也算）；点列表上方的锁图标可以马上锁上；刷新页面、重开程序也会锁上。
- 解锁要算大约一秒（故意的，让别人猜密码变慢）。

### 改主密码

列表上方的钥匙图标。改完马上生效，条目不用重新加密。
别的电脑合并到这次修改之后，也要用新的主密码；以前的备份还是用当时的主密码。

改主密码只是把同一把「密码库密钥」换一个主密码重新包起来，密钥本身不变。
所以如果旧主密码已经泄露，而且对方拿到过当时的数据（数据库、备份，或者在局域网里从接口读过），改主密码拦不住他继续解开之后的内容。
那种情况下要把里面的密码逐个换掉；目前还没有「换一把密钥重新加密全部条目」的功能。

## 2. AI 取用

AI（Claude Code、Codex 等，通过 MCP）不能直接读密码库：

1. 它只能先看到有哪些条目：名称和种类，没有内容（`xpanel_vault_list`）。还没整理的条目它不能取用。
2. 它要用某一条时发一个请求，说明用途（`xpanel_vault_get`）。**必须用 API key**：在主机上 `xp key create <名字>` 生成，配在 MCP 的 `XPANEL_KEY` 里。
3. 开着的 xpanel 界面（桌面版或网页版）会弹窗，写着：
   - 谁：它用的 API key 的名字；
   - 哪一条：密码库锁着时要先在弹窗里输主密码解开，才显示这一条真正的名称（密文里的那份）；
   - 它说：它自己写的用途。
4. 你点「允许这一次」，那一条的全部内容才会交给它；点「拒绝」或两分钟不理，它什么都拿不到。

- 每次取用都要确认，没有「以后都允许」。
- 在弹窗里输主密码只解开这一条、只用于这一次，不会顺便把整个密码库打开；按回车只是解开，允许要另外点。
- 弹窗刚出来的一秒多「允许」是灰的，免得正在别处敲回车时顺手批准了。
- 弹窗关不掉，要给个答复：允许、拒绝，或者等两分钟它自己作废。
- 同一个 API key 对同一条同时只能有一个请求，等确认的请求最多 5 个。
- 允许和拒绝都会记在操作记录里（谁、哪一条、什么时候）。
- 「它说」是对方自己写的，不一定可信。不是你刚让它做的事，就点拒绝。
- 交出去的内容你就管不了了：AI 会在它自己的对话里看到明文。

「交给 AI」展开的项目目录、评论里 @AI 带的上下文、条目的导出和搜索里都没有密码库的内容。

## 3. 多台电脑

- **连接到主机的电脑、浏览器**：密码库在主机上，随时是最新的。连不上主机时用不了密码库（离线缓存里没有它）。
- **外置硬盘同步**：密码库跟着一起合并，不用选。
  - 只有一台电脑改过的条目，跟着改；一台电脑删了的，跟着删。
  - 两台电脑都改了同一条：留较新的，较旧的另存成一条，名称后面带「（合并时保留的旧版本）」。看过之后自己删掉不要的。
  - 主密码以较晚改的那次为准。
- **两台电脑各自设了主密码，后来才合并**：两边的条目都在，各用各的主密码。
  - 解锁时输哪个主密码，就解开哪一边的条目；另一边的显示「用另一个主密码加密的」，点开输另一个主密码就能看。
  - 想以后输一次就全解开：用「改主密码」把其中一个改成和另一个一样。
  - 最好一开始只在一台电脑上设主密码，其他电脑通过合并或连接主机拿到它。

## 4. 安全方面你需要知道的

xpanel 的接口在局域网里不用登录（API key 只是用来标明是谁），网页版走的是明文 HTTP。密码库是在这个前提下设计的。

**加密是怎么做的**

- 加密、解密都在界面里做（你面前这台电脑的 xpanel 窗口或浏览器页面）。主密码和解开的内容不发给主机，也不写到硬盘。
- 主密码经过 scrypt（N=2^17, r=8, p=1）算出一个密钥，用它把随机生成的「密码库密钥」包起来存在主机上。
- 每一条的内容（包括名称和种类）用密码库密钥加密（XChaCha20-Poly1305，每次保存换一个随机数）。
- 改动密码库（存、改、删、改主密码、批准取用）都要带一个校验值（HMAC-SHA256），只有解开了密码库的界面算得出来。
- 交给 AI 的那一条，用它请求里带的临时公钥加密（X25519 + HKDF-SHA256 + XChaCha20-Poly1305）后经主机转交。
- 用的是开源库 `@noble/ciphers`、`@noble/hashes`、`@noble/curves`（界面）和 RustCrypto 的 `chacha20poly1305`、`x25519-dalek`、`hkdf`、`hmac`（主机和命令行）。

**它防得住什么**

- 别人拿到数据库文件、备份、外置硬盘：只有密文和名称，没有主密码打不开。
- 局域网里有人只是抓包（不改数据包）：看不到主密码和内容，交给 AI 的那一条在路上也是密文。
- 局域网里别的设备、手里有 API key 的 AI 直接调接口：
  - 读不到内容；
  - 改不了、删不了条目，换不掉钥匙（没有校验值）；
  - 不能把一条的密文挂到另一个名称下面骗你批准（界面以密文里的名称为准）；
  - 不能冒充你点「允许」；没有 API key 的不能发取用请求。
- 你在浏览器里打开的别的网站：读不到也调不了密码库的接口（其他接口它们调得到，这是原来就有的）。

**它防不住什么**

- **主密码太弱**：密文和包着的密钥，局域网里的设备都能从接口读到，可以拿回去慢慢猜。主密码是唯一的防线。
- **你用的这台电脑不干净**：键盘记录、恶意浏览器插件、别人能动你解锁着的电脑，都看得到解开的内容。
- **局域网里有人能改数据包**（不只是看）：网页版是明文 HTTP，他可以把页面换成偷主密码的版本。不放心的网络里只用桌面版，或者等远程访问（Tailscale）做好后走加密通道。
- **局域网里有人抓到了 API key**：API key 也是明文传的。拿到它的人可以冒充那个 AI 发取用请求（弹窗里看起来一样），你批准了内容就交给他。所以批准之前想一下：是不是我刚让它做的事。
- **拿到过数据库文件或备份、人又在局域网里**：他解不开内容，但数据库里存着校验密钥，所以能伪造改动：删条目、把密文改乱、把钥匙换掉让你打不开。
  发现条目莫名其妙变了或打不开，从备份恢复，并且把外置硬盘、备份文件夹看好。
- **往「待整理」里塞东西**：锁着也能存，意味着局域网里别的设备也能往「待整理」里放一条（它看不到任何内容）。待整理的条目整理时自己过一眼。
- **有人捣乱**：局域网里的设备可以替你点「拒绝」、发一堆请求占住名额、在你还没设主密码之前抢先设一个。这些只会让你用不了，拿不到内容。
- **名称和数量**：名称、种类、有多少条、什么时候改的，都是明文。
- **旧主密码泄露**：见上面「改主密码」。旧备份用旧主密码也打得开。
- **交给 AI 之后**：内容在它的对话里是明文，它怎么用、会不会写到别处，xpanel 管不了。
- **复制到剪贴板的内容**：不会自动清掉。

## 5. 出问题时

| 情况 | 怎么办 |
|---|---|
| 忘了主密码 | 没有办法找回。只能到各个网站重置密码后重新存 |
| 「这一条在别处刚改过…」 | 另一台电脑或另一个窗口刚改了同一条。把要留的内容复制出来，点取消，重新选中它再改 |
| 「密码库没解锁，或者这次改动不是从解锁了的界面发来的」 | 一般是界面太旧或者主密码刚在别处改过。刷新页面重新解锁 |
| AI 说「取用密码库要带 API key」 | 在主机上 `xp key create <名字> --data <数据文件夹>`，把得到的 key 配到 MCP 的 `XPANEL_KEY` |
| 「主密码在别处刚改过」 | 别处刚改了主密码。刷新页面，用新的主密码解锁 |
| 「打不开密码库……连不上主机」 | 密码库存在主机上，等连上主机再用 |
| 合并后多了「（合并时保留的旧版本）」 | 两台电脑都改了同一条。对比一下，删掉不要的那条 |
| 误删了一条 | 从每天的备份里找回：见 [drive-sync.md](drive-sync.md) 第 5 节恢复数据库的办法（整库恢复） |

## 6. 实现说明（给开发者）

- 数据库（schema v6）：`vault_keys`（钥匙：`kid`、`data` = `{kdf, salt, n, c, auth}`）、`secrets`（`id`、`kid`、`title`、`kind`、`data` = `{n, c}`，软删除）。和 `items` 分开，所以不会进条目的列表、搜索、导出、旧界面的 `/api/state`。时间都是整数毫秒（要放进校验串）。
- 存储：`crates/xp-store/src/vault.rs`。
  - 写操作都过 `check_mac`：HMAC-SHA256(校验密钥, 各部分用 `\n` 连起来)。校验密钥 = HKDF-SHA256(密码库密钥, info `xpanel-vault-auth-v1`)，建钥匙时由界面交给主机存在 `data.auth`，之后不再往外给，改主密码时沿用。
    校验串：`put-secret|id|kid|title|kind|n|c|expect`、`delete-secret|id|expect`、`put-key|kid|salt|n|c|N|r|p|expect`、`resolve|请求号|epk|n|c`。
  - `expect` 是上次看到的 `updatedAt`，对不上返回冲突；它也在校验串里，所以抓到的旧请求不能重放。删掉的标识不能再用。
    （例外：整库恢复到旧备份后，那之后抓到的请求又对得上了。局域网里有人抓包的环境下恢复过数据库，留意一下条目有没有被改回去。）
  - 合并时，同一把钥匙只接受校验密钥相同的新版本（正常改主密码不会变它）。
  - 取用请求只在内存里（`Store.vault_requests`），两分钟过期，批准后取走一次就删；同一个调用方对同一条只能有一个，总数最多 5 个。
  - 外置硬盘合并在 `merge_vault`（`sync.rs` 的 `merge_apply` 调它）。另存的旧版本换了 id 和主机上的名称，密文不变。
- 接口：`crates/xp-server/src/vault.rs`。`same_site_only` 挡住别的网站的网页（Origin 和 Host 不一致、Host 不像局域网地址、`Sec-Fetch-Site: cross-site`）；`POST /vault/requests` 用 `KeyActor`，只认验证过的 API key。
  附件（`/api/asset/*`）带 `Content-Security-Policy: sandbox` 和 `nosniff`：附件谁都能传，带脚本的 SVG 直接打开时不能以这个站点的身份跑，否则上面这道检查就白做了。
- 界面：`web/src/lib/vault.ts`（加解密、校验值、解锁状态、读写）、`web/src/components/Vault.tsx`（整页 + `VaultRequests` 弹窗，挂在 `App.tsx`）。
  - 用纯 JS 的 @noble 库而不是 `crypto.subtle`：局域网里用 `http://主机:8765` 打开时浏览器不提供后者。
  - 密文里的 JSON 带 `title`、`kind`，解开后界面只认这一份；主机上的 `title` 列只是标签。**不要改成显示主机上的名称**，否则可以把一条的密文换到另一个名称下骗用户批准。
  - 主机给的 scrypt 参数只接受 N 在 2^15 到 2^18 之间、r=8、p≤2。
- 随手记：钥匙有一对「只进不出」的 X25519 密钥，私钥 = HKDF-SHA256(密码库密钥, info `xpanel-vault-box-v1`)，公钥登记在钥匙的 `data.pub`
  （`PUT /vault/keys/{id}/box`，要校验值；旧钥匙解锁后由界面补登记）。`POST /vault/drops` 收的是用公钥加密的原文（和交给 AI 的封装方式一样，
  info 换成 `xpanel-vault-drop-v1`），不要校验值，存成 `kind = raw`、`data` 里带 `epk`，最多攒 300 条。整理 = 用普通的保存接口改写这一条（换成密码库密钥加密）。
  界面：`lib/vault.ts` 的 `dropSecret`；`lib/vaultParse.ts`（从原文里拆各栏、判断一段话像不像账号密码）；快速记录选「密码」时打的字只放在内存里，不进草稿。
- 转入密码库的收件箱消息：`Store::scrub_item`（`POST /items/{id}/scrub`）把条目内容换成空的并留删除标记，清掉全文索引和操作记录里的前后内容，
  开 `secure_delete` 让 SQLite 把旧内容盖掉，再把日志文件并回主文件。
- 搜索：`lib/vaultSearch.ts`（打分、容错、用过的次数）+ `components/VaultPalette.tsx`（Ctrl+K）。标签、置顶、原文都在密文的 JSON 里。
- MCP：`crates/xp-cli/src/vault.rs`（临时密钥、等确认、解开）+ `mcp.rs` 的 `xpanel_vault_list`、`xpanel_vault_get`。
- 格式里的常量：钥匙的附加数据 `xpanel-vault-key-v1`，条目的 `xpanel-vault-secret-v1`，取用请求的 HKDF info `xpanel-vault-request-v1`（盐是「界面的临时公钥 ‖ 请求方公钥」）。改格式时换一个版本号，别原地改。
- 测试：`cargo test -p xp-store vault`、`cargo test -p xp-server vault`、`cargo test -p xp-cli`。界面的端到端测试还没进仓库（做法见 development.md 第 5 节：在明文 HTTP 的非 localhost 地址上走一遍，确认数据库文件和请求里都没有明文，再用接口试着换密文、冒充批准、跨站读取，都应该被拒绝）。
