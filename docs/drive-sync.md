# 外置硬盘同步：带着数据去另一台电脑

把 xpanel 的整份数据（笔记、事项、评论、关联、设备、分类、收件箱，以及所有图片和附件）和外置硬盘上的一个文件夹同步。
出差时把硬盘插到笔记本或 Mac 上接着用，回来再同步回主机。

---

## 1. 它是怎么同步的

- 两边都是**完整的数据文件夹**：`xpanel.db`（数据库）和 `assets/`（图片、附件）。
- 每次同步完，两边的数据库里会记下同一个「同步标记」。下次同步时，谁在标记之后改过，谁就是「改过的一边」。

| 情况 | 会发生什么 |
|---|---|
| 外置硬盘上还没有数据 | 把本机的完整复制过去 |
| 只有本机改过 | 本机 → 外置硬盘 |
| 只有外置硬盘改过（在别的电脑上用过） | 外置硬盘 → 本机 |
| 两边都没改 | 提示「两边已经一致」，只补齐附件 |
| 两边都改过，或者两个文件夹从没一起同步过 | **不会自动覆盖**，让你选用哪边的 |

- **被覆盖的一边会先备份**到它自己的 `backups/` 文件夹，文件名是 `before-sync-日期-秒数.db`。
- 附件两边互相补齐，只增不删。
- 复制数据库用的是 SQLite 自带的备份接口，本机的 xpanel 开着也能同步，得到的是完整一致的数据。

> 注意：这不是「合并」。两边都改过时只能保留一边的数据库，另一边的改动留在备份里，需要的话手动找回（见第 5 节）。
> 所以**同一时间只在一台电脑上用**，换电脑之前先同步。

---

## 2. 准备（只需要做一次）

1. **外置硬盘的格式**
   - 只在 Windows 之间用：NTFS 或 exFAT 都行。
   - 要插到 Mac 上用：必须是 **exFAT**。NTFS 的盘在 Mac 上只能读、不能写。
   - 查看方法：Windows 资源管理器里右键硬盘 →「属性」→「文件系统」。
2. **每台要用的电脑都装同一个版本的 xpanel**
   - 先在主机上推送代码：`git push --force-with-lease origin main phase1-foundation`。
   - 其他电脑上拉代码后构建：Windows 用 `build-windows.bat`，Mac 用 `build-mac.sh`。
   - 版本不一致时，旧版打不开新版写的数据，同步会提示「请先升级」。
3. 在硬盘上建一个文件夹用来放数据，比如 `F:\xpanel`（Mac 上是 `/Volumes/硬盘名/xpanel`），建空文件夹即可。

## 3. 日常操作

同步入口有三个：

- 左下角状态栏的**硬盘图标**
- 「设置」→「外置硬盘同步」
- 命令行 `xp sync`（见第 6 节）

窗口里：

1. 填外置硬盘上的文件夹（会记住上次用的）。
2. 点「检查」，查看两边各有多少条、多少附件、最近修改时间，以及哪边改过。
3. 按提示点按钮：
   - 「复制到外置硬盘」或「用外置硬盘的更新本机」：只有一边改过时出现。
   - 「用本机的（覆盖外置硬盘）」和「用外置硬盘的（覆盖本机）」：两边都改过、或者从没一起同步过时出现，需要你来选。

> 只有「本机存储」模式的电脑能同步。「连接到主机」模式的电脑，数据在主机上，请在主机上同步。

---

## 4. 出差流程（示例：台式机 BASE 是主机，出差带笔记本）

### 走之前（在台式机上）

1. 插上外置硬盘，打开同步窗口，文件夹填 `F:\xpanel`。
2. 点「检查」，再点「复制到外置硬盘」。
3. 完全退出台式机上的 xpanel（托盘图标也退出），然后安全弹出硬盘。

### 出差时（在笔记本上）

两种用法，任选一种：

**用法 A：直接用硬盘上的数据（最简单）**

1. 插上硬盘。
2. 打开「设置」→ 选「本机存储」，「数据文件夹」填硬盘上的文件夹（盘符以实际为准，比如 `E:\xpanel`；Mac 上是 `/Volumes/硬盘名/xpanel`），保存。
3. 正常使用。所有修改直接写在硬盘上。
4. 拔硬盘前先退出 xpanel。

**用法 B：笔记本用自己的文件夹，硬盘只做中转**

1. 笔记本的「数据文件夹」保持笔记本本地的（比如 `D:\xpanel`）。
2. 插上硬盘，同步一次，笔记本就拿到了台式机的数据。
3. 出差期间正常使用。
4. 回来前再同步一次，把出差时的修改写回硬盘。

> 用法 A 不用记得同步，但拔掉硬盘就没法用。用法 B 可以不带硬盘到处用，但要记得回来前同步。

### 回来后（在台式机上）

1. 插上硬盘，打开同步窗口，点「检查」。
2. 正常情况下会显示「那边在上次同步后改过」，点「用外置硬盘的更新本机」。
3. 完成。台式机原来的数据库已备份在 `D:\xpanel\backups\before-sync-*.db`。

## 5. 出问题时怎么办

### 两边都改过（提示「上次同步后两边都改过」）

说明出差期间台式机上也有人改过数据，比如 AI 通过 MCP 写入，或者忘了退出。

1. 对比窗口里两边的条目数和最近修改时间，保留改动更多、更重要的一边。
2. 被覆盖的一边在它的 `backups/before-sync-*.db` 里。另一边零散的改动，可以用第 3 步的方法临时打开备份，手动复制回来。

### 同步错了，想恢复

1. 完全退出 xpanel。
2. 打开数据文件夹里的 `backups/`，找到对应时间的 `before-sync-日期-秒数.db`；每天自动备份的 `xpanel-日期.db` 也可以用。
3. 把当前的 `xpanel.db` 改名留底（比如 `xpanel.db.bad`），同时删掉 `xpanel.db-wal` 和 `xpanel.db-shm`。
4. 把备份文件复制过来，改名为 `xpanel.db`。
5. 重新打开 xpanel。

### 其他提示

| 提示 | 原因和处理 |
|---|---|
| 「同步的文件夹就是本机的数据文件夹」 | 笔记本用的是用法 A，数据本来就在硬盘上，不需要同步 |
| 「那边的数据是更新版本的 xpanel 写的」 | 这台电脑的 xpanel 太旧，先拉代码重新构建 |
| 「替换 … 失败（那边是不是有 xpanel 正开着？）」 | 另一台电脑正在用这块硬盘，先退出那边的 xpanel |
| 「只有本机存储模式可以同步」 | 这台是连接模式，去主机上同步，或者在设置里改成本机存储 |

## 6. 命令行

适合写脚本或定时任务。`xp` 由 `build-windows.bat` / `build-mac.sh` 一起装好。

```bash
# 只看会怎么同步，不改任何东西
xp sync --data D:\xpanel F:\xpanel --dry-run

# 自动同步（只有一边改过时才会执行）
xp sync --data D:\xpanel F:\xpanel

# 两边都改过时指定方向
xp sync --data D:\xpanel F:\xpanel --push   # 用本机的覆盖外置硬盘
xp sync --data D:\xpanel F:\xpanel --pull   # 用外置硬盘的覆盖本机
```

Mac 上把路径换成 `~/xpanel` 和 `/Volumes/硬盘名/xpanel`。`--data` 也可以用环境变量 `XPANEL_DATA` 代替。

---

## 7. 哪些会同步，哪些不会

| 会同步 | 不会同步 |
|---|---|
| 所有条目（笔记、事项、入口、规范、收件箱），包括评论、关联、子笔记、AI 进展 | 每台电脑自己的设置（AI 命令、端口、这台电脑是哪台设备等，存在系统的应用配置目录里） |
| 设备、分类、标签、微信聊天记录、任务模板、API key | 每天的自动备份（`backups/` 各留各的） |
| 图片和附件（`assets/`） | 冷备份文件夹的设置 |

## 8. 实现说明（给开发者）

- 代码：`crates/xp-store/src/sync.rs`，桌面版命令 `sync_plan` / `sync_run`（`src-tauri/src/lib.rs`），界面 `web/src/dialogs/DriveSync.tsx`，命令行 `xp sync`（`crates/xp-cli`）。
- 同步标记存在数据库 `meta` 表的 `sync_mark`：`{id, rev}`。`rev` 是每次写入都会加一的版本号，和标记里的不一样就说明改过。
- 推送（本机 → 外置）：先把外置硬盘上原来的数据库备份到它的 `backups/`，再把本机数据库在线备份到临时文件，删掉外置硬盘上旧的 `-wal` / `-shm` 后换上新文件。
- 拉取（外置 → 本机）：先把本机数据库备份到 `backups/`，再用 SQLite 的 restore 接口把外置硬盘的数据库恢复到正在用的连接上。之后给两边都写上同一个新 `rev` 和标记，保证界面一定会刷新。
- 测试：`cargo test -p xp-store syncs_with_an_external_folder`。
