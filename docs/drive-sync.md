# 外置硬盘同步：换电脑、带着数据出差

每台电脑用自己的数据文件夹，外置硬盘负责交接：离开一台电脑前把数据**备份到外置硬盘**，到另一台电脑**从外置硬盘合并**。
合并按条目来：只有一边改过的条目直接用改过的那边，两边都改过的由你逐条选。

---

## 1. 它是怎么工作的

- 外置硬盘上的文件夹（比如 `F:\xpanel`）里有一个 `xpanel-backup/`：

  ```text
  F:\xpanel\xpanel-backup\
    snapshots\xpanel-日期-时间-电脑标识.db   每次「备份到外置硬盘」的完整数据库，保留最近 6 份
    assets\                                  图片和附件，只增不删
    latest.json                              最近一次备份是哪台电脑、哪一份
  ```

- 每台电脑的数据文件夹有自己的标识和名字（名字取这台电脑在设备表里的名字），每条条目记着最后是在哪台电脑改的。
- 每次备份或合并之后，本机会留一份「同步点」（数据文件夹的 `sync/base.db`），就是当时和外置硬盘对齐的那份数据。
- 合并时拿三份数据比：**本机现在的**、**外置硬盘上最新的备份**、**同步点**。

| 这条条目 | 合并时 |
|---|---|
| 只有另一台电脑改过（新增、修改、删除） | 默认用外置硬盘上的，可以改成保留本机的 |
| 只有本机改过 | 不出现在列表里，原样保留，下次备份带过去 |
| 两边都改过 | 标成「两边都改过」，默认选较新的那边；可以选用外置硬盘的、保留本机的，或两份都留 |
| 两边一样 | 不出现 |

- 「两份都留」会把外置硬盘上的那份另存成一条新的，标题后面带「（某台电脑的版本）」。
- 附件、分类、设备、导入的微信聊天只增不减，直接合到一起，不用选。
- **合并前本机自动留一份备份**：数据文件夹的 `backups/premerge-日期-时间.db`，保留最近 6 份。
- 外置硬盘上最新的备份来自别的电脑、而本机还没合并过时，「备份到外置硬盘」会先让你合并，免得把那边的改动盖掉。

> 同步点只有在外置硬盘上那份备份「包含过它」时才能用。下面几种情况没有可用的同步点，分不出是哪边改的，
> 两边不一样的条目都算「两边都改过」，默认选较新的，请过一遍列表：
> 第一次和这块硬盘合并；另一台电脑没合并就直接备份过；换了一块硬盘；本机恢复过旧的数据库。

## 2. 准备（只需要做一次）

1. **外置硬盘的格式**
   - 只在 Windows 之间用：NTFS 或 exFAT 都行。
   - 要插到 Mac 上用：必须是 **exFAT**。NTFS 的盘在 Mac 上只能读、不能写。
2. **每台电脑装同一个版本的 xpanel**：Windows 用 `build-windows.bat`，Mac 用 `build-mac.sh`。
   旧版读不了新版写的备份，合并时会提示升级。
3. 每台电脑在「设置」里选「这台电脑存数据（主机）」，数据文件夹用本机硬盘上的（比如 `D:\xpanel`）。
4. 在「设备」里选好「这台电脑是哪台」，合并时就能看到每条是在哪台电脑改的。

## 3. 日常操作

入口：左下角状态栏的**硬盘图标**，或「设置」→「外置硬盘同步」。命令行见第 6 节。

1. 填外置硬盘上的文件夹（会记住；文件夹还没建的话备份时自动建），点「检查」。
2. 窗口上方显示本机上次对齐的时间，和外置硬盘上最近一次备份是哪台电脑、什么时候做的。
3. 外置硬盘上有别的电脑的新备份时，下面列出不一样的条目：
   - 每条右边选「用外置硬盘的 / 保留本机的」，两边都改过的还能选「两份都留」。
   - 「全部用外置硬盘的」「全部保留本机的」可以一次选完。
   - 选好后点「合并」。
4. 没有要合并的，就点「备份到外置硬盘」。等出现「已备份到外置硬盘」的提示再拔硬盘。

> 「连接到主机」模式的电脑和浏览器里的网页版也能打开这个窗口，操作的是**主机**上的数据，硬盘要插在主机上，文件夹也只能在主机的桌面版里改。

## 4. 出差流程（示例：台式机在家，出差带笔记本）

### 走之前（在台式机上）

1. 插上外置硬盘，打开同步窗口。
2. 如果列表里有笔记本上次带回来的改动，先合并。
3. 点「备份到外置硬盘」，等提示出现后安全弹出硬盘。

### 出差时（在笔记本上）

1. 插上硬盘，打开同步窗口，点「检查」。
2. 列表里是台式机上改过的条目，点「合并」。
3. 正常使用，硬盘可以拔掉。
4. 回来前插上硬盘，点「备份到外置硬盘」。

### 回来后（在台式机上）

1. 插上硬盘，打开同步窗口，合并笔记本上的改动。
2. 出差期间台式机上也改过的条目（比如 AI 通过 MCP 写的）会标成「两边都改过」，逐条选。
3. 最后点一次「备份到外置硬盘」，让硬盘上的备份是最新的。

## 5. 出问题时怎么办

### 合并错了，想恢复

1. 完全退出 xpanel。
2. 打开数据文件夹里的 `backups/`，找到合并前的 `premerge-日期-时间.db`（每天自动备份的 `xpanel-日期.db` 也可以用）。
3. 把当前的 `xpanel.db` 改名留底（比如 `xpanel.db.bad`），同时删掉 `xpanel.db-wal` 和 `xpanel.db-shm`。
4. 把备份文件复制过来，改名为 `xpanel.db`，重新打开 xpanel。
5. 再打开同步窗口：外置硬盘上那份备份会重新列出来，这次两边不一样的都算「两边都改过」，重新选一遍。

单条合错了也可以不整体恢复：「操作记录」（`GET /api/v1/audit`）里记着每条合并前后的内容。

### 不想合并，直接备份

点「不合并，直接备份」再确认一次。外置硬盘上那份备份还在 `snapshots/` 里（保留最近 6 份），但本机不会再提示合并它。
另一台电脑下次合并时，因为这份备份没有包含它的改动，两边不一样的条目都会算「两边都改过」，要逐条确认，不会被悄悄盖掉。

### 常见提示

| 提示 | 原因和处理 |
|---|---|
| 「还没设置外置硬盘上的文件夹」 | 在同步窗口里填一个，比如 `F:\xpanel` |
| 「文件夹 … 不在，外置硬盘插上了吗？」 | 硬盘没插、盘符变了，或者路径填错 |
| 「外置硬盘上的文件夹不能是本机的数据文件夹或它里面的文件夹」 | 换一个文件夹 |
| 「外置硬盘上还没有备份」 | 先在另一台电脑上点「备份到外置硬盘」 |
| 「外置硬盘上的备份刚刚变了」 | 打开窗口后别的电脑又备份过，重新点「检查」 |
| 「数据库版本 … 比程序支持的新，请升级 xpanel」 | 这台电脑的 xpanel 太旧，拉代码重新构建 |

## 6. 命令行

适合写脚本或定时任务。`xp` 由 `build-windows.bat` / `build-mac.sh` 一起装好。

```bash
# 只看会合并什么：不合并，也不备份
xp sync --data D:\xpanel F:\xpanel --dry-run

# 先合并外置硬盘上别的电脑的改动，再把本机的数据备份过去
xp sync --data D:\xpanel F:\xpanel

# 有两边都改过的条目时要说用哪边，否则不合并
xp sync --data D:\xpanel F:\xpanel --prefer newer   # 较新的那边
xp sync --data D:\xpanel F:\xpanel --prefer drive   # 外置硬盘上的
xp sync --data D:\xpanel F:\xpanel --prefer local   # 本机的
xp sync --data D:\xpanel F:\xpanel --prefer both    # 两份都留
```

- Mac 上把路径换成 `~/xpanel` 和 `/Volumes/硬盘名/xpanel`。`--data` 也可以用环境变量 `XPANEL_DATA` 代替。
- 命令行直接读写数据文件夹，建议先退出这台电脑上的桌面版再跑。
- 只开服务不开窗口时：`xp serve --data … --drive F:\xpanel`，然后在网页版里操作，或者调接口 `/api/v1/backup`、`/api/v1/backup/merge`。

## 7. 哪些会合并，哪些不会

| 会合并 | 不会合并 |
|---|---|
| 所有条目（笔记、事项、入口、规范、收件箱），包括评论、关联、子笔记、AI 进展 | 每台电脑自己的设置（AI 命令、端口、这台电脑是哪台设备等） |
| 图片和附件（`assets/`） | API key、操作记录（各留各的） |
| 手工建的分类、设备、导入的微信聊天 | 每天的自动备份（`backups/` 各留各的）和冷备份 |
| 任务模板、收件箱里「哪些是我」（只在本机没设过时带过来） | |
| 密码库（密文，不用选；两边都改了同一条时留较新的，旧的另存一条，见 [vault.md](vault.md)） | |

## 8. 和以前的整库同步的区别

2026-10 之前的「外置硬盘同步」是整个数据库互相覆盖：两边都改过时只能留一边。现在换成了按条目合并。

- 外置硬盘上以前同步出来的 `xpanel.db` 和 `assets/` 不再使用，确认数据都在某台电脑上之后可以删掉。新的数据放在同一个文件夹下的 `xpanel-backup/` 里。
- 冷备份文件夹（设置里的「冷备份文件夹」）还是每天自动复制一份备份过去，和外置硬盘同步是两个设置。没单独填外置硬盘的文件夹时，同步窗口用冷备份文件夹。

## 9. 实现说明（给开发者）

- 代码：`crates/xp-store/src/backup.rs`（`backup_to_drive`、`backup_status`）、`crates/xp-store/src/sync.rs`（三方对比、`merge_preview`、`merge_apply`）。
- 接口：`GET/POST /api/v1/backup`、`GET/POST /api/v1/backup/merge`（`crates/xp-server/src/v1.rs`）。界面 `web/src/dialogs/DriveSync.tsx` 通过 `lib/api.ts` 的 `drive` 调用，桌面版和浏览器走同一套。
- 外置硬盘上的文件夹：桌面版配置的 `syncDir`，命令 `set_sync_dir`（`src-tauri/src/lib.rs`）写配置并调 `Store::set_drive_dir`；`xp serve --drive`、`xp sync` 也是调它。
- 数据库：`items.origin` 列（最后在哪个数据文件夹改的）；`meta` 表的 `replica_id`、`replica_name`、`replicas`（认识的电脑）、`sync_base`（上次对齐的那份备份的 `latest.json`）、
  `sync_lineage`（本机的数据包含过哪些备份）。
- 同步点能不能用（`base_rows`）：`sync/base.json` 记着 `base.db` 是哪份，要和 `sync_base` 一致；外置硬盘上那份备份的 `latest.json` 里的 `lineage` 要包含它。
  对不上就按没有同步点处理。
- 数据文件夹被整个复制到另一台电脑时（机器名变了），`init_replica` 会换一个新标识并清掉同步点。
- 测试：`cargo test -p xp-store`（`merge_between_two_computers`、`one_click_backup_to_drive`、`stale_sync_point_is_not_trusted`、`drive_dir_is_separate_from_cold_backup`）。
